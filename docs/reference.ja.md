# 操作・設定リファレンス

v0.5.0では、コマンドラインと `--json`、コミット検索のフィルタ、`y` によるコピー、
ユーザー定義の作業ツールコマンド、ブランチ単位のCIとプルリクエスト信号、
そして「不明」と「正常」を区別するHome行が加わりました。従来からの、設定とRepository Finderのマウス選択、タイトルバーの
ナビゲーションと結果クリックが利用できます。
タイトルバーの `[戻る]`・`[Home]`・`[移動]` を操作でき、`[移動]` から設定、Worktree、
横断メンバー、コミット検索へ移動できます。ポップアップは `Esc` または外側のクリックで閉じます。

v0.5.0 を対象とします。[利用マニュアル](manual.ja.html) · [README](../README.ja.md)

### 5. コミット検索（Home で `S`）

| キー | 動作 |
|---|---|
| `/` | 新しい検索を開始 |
| `author:` / `path:` | 作者・パスで絞り込み — `author:jane path:src/` |
| `since:` / `until:` | 期間で絞り込み — `since:2.weeks until:2024-01-01` |
| `Enter` | 選択コミットの差分を開く（該当リポジトリへ移動） |
| `Esc` | Home へ戻る |

フィルタは同じ1行のプロンプト内で空白区切りのトークンとして書きます。それ以外の語は
これまでどおりメッセージ本文として扱うため、`fix: auth` や `fix(auth):` もそのまま検索できます。
空白を含む値は引用符で囲み（`author:"Jane Doe"`）、トークン全体を引用符で囲むと
（`"path:"`）その文字列そのものを検索します。`author:` は `members.json` で同一人物に
統合した別名にも一致するため、正式名で検索してもその人の別名のコミットが見つかります。
`author:` と `path:` は複数指定でき git 側で OR になります。`since:` / `until:` を複数書いた
場合は最後の指定が有効です。値を `-` で始めたり制御文字を含めたりはできません。解釈できない
クエリは画面を空にせず前回の結果を残します。件数は1リポジトリ50件・全体300件が上限で、
上限に達した場合はどちらの上限か、何リポジトリが該当したかを見出しに表示します。

### 9. ツールメニュー（`O`）

| キー | 動作 |
|---|---|
| `t` / `e` / `l` / `g` | シェル / エディタ / lazygit / GitUI |
| `1` – `6` | 対応する独自コマンドを実行 |
| `c` | エディタコマンド設定（既定: `code`） |
| `w` | エディタ終了待機（既定: オフ。端末内エディタはオン） |
| `x` | 独自コマンドを追加・編集・削除 |
| `y` | このパスをコピー |
| `Esc` / `q` | メニューを閉じる |

設定例と対応範囲は[マニュアル](manual.ja.html#editor-examples)を参照してください。

`y` は選択中の対象に応じた識別子をコピーします。Commits ではコミットハッシュ、Branches では
ブランチ名、タグ名、stash の参照名、Contributors では作者のメールアドレス（`git log --author=`
が求める値）、Status と差分画面ではファイルの絶対パス、それ以外ではリポジトリまたは Worktree の
パスです。端末へは OSC 52 シーケンスとして送るため、既定で無視する端末も多く（tmux では
`set-clipboard on` が必要）、確認メッセージはクリップボードへの書き込み成功ではなく
「送信した」ことのみを伝えます。送る文字列は制御文字を除去し、長すぎる場合は送りません。

## Home 行の読み方

| 表示 | 意味 |
|---|---|
| `↑2 ↓1` | 最後のfetch時点での upstream に対する先行 / 遅れのコミット数 |
| `↑? ↓?` | 比較対象がありません。リモートがないか、一度もpushしていないブランチで、どちらであるかはパネルに表示します。v0.5.0より前のキャッシュから復元した行もこの表示になります（当時のキャッシュが答を記録していないため、この場合パネルにも追記はありません） |
| `2M 5?` | 追跡対象の変更2件と未追跡5件。古いキャッシュから復元した行は内訳を推測せず合計のみを表示します |
| `0` | 作業ツリーがクリーン |
| `⚠ パスなし` / `⚠ Git管理外` / `⚠ 読取不可` | 登録自体を読み取れません。他の列は `—` になり、パネルが理由の全文を表示し、`n` でも抽出できます |
| `…` | 未取得 |
| `~/…/repo` | 短縮したパス。末尾ではなく中間を省略するので、識別に必要な末端は必ず残ります |
| スピナーと操作名 | pull・fetch・行の再読込の実行中。その値を書き換える操作なので Sync 列を置き換えます |

Branch 列はブランチ名に続けて、そのブランチに起きていることを表示します。
ブランチ名より後ろは、幅が足りないとき**途中で切らずに項目ごと**落とします。
落とす順は重要度の低いものからなので、`[PR:50]` は消えることはあっても
`[PR:5]` に化けることはありません。

| 表示 | 意味 |
|---|---|
| `⚠MERGE` / `⚠REBASE` / `⚠2conflict` | 中断中の操作、または未解決のコンフリクト。幅が狭くても落としません |
| `#42` | このブランチから作られたプルリクエスト |
| `✗rev` / `✓rev` | そのPRに変更要求が来ている / 承認済み。レビュー待ちのままの状態は表示しません（オープン中のPRの既定値のため） |
| `draft` | そのPRは下書き。最初に落とす項目です（下書きは選択であって作業ではないため） |
| `[REV:3]` | このリポジトリで**自分の**レビューを待っているPRが3件 |
| `[PR:7]` | オープン中のPRの総数。100件を超えると `100+` |
| `✓CI` / `✗CI` / `●CI` | このブランチの最新CIが成功 / 失敗 / それ以外（実行中・中止・要対応） |
| `—CI` / `⏱CI` / `?CI` | CIの答そのものがありません。detached HEAD・取得のタイムアウト・取得失敗の順。空白は「問題なし」に見えるため、必ず印を出します |

`?` を使う表示は3つあり、いずれも列ごとに「不明」を意味します — Sync の `↑? ↓?`、
Dirty の `5?`（未追跡ファイル数）、Branch の `?CI`。同様に `—` はどちらの場所でも
「値がない」ことを表します（読み取れない行の他の列と、`—CI`）。

選択リポジトリのパネルは2種類の時刻を並べて表示します。両者は別の問いに答えるためです。
**ローカル読取（作業ツリー）** はこのツールが最後に git を実行した時刻、
**リモート取得（↑↓）** は `FETCH_HEAD` の更新時刻、すなわち ahead/behind の鮮度で、
これは fetch でしか新しくなりません。`フェッチ履歴なし`・`未記録`・`ssh://` 登録では
`取得不可（リモート）` と表示します。

CI の行は、その結果がどのブランチのものかを明示します。状態は取得済み・実行なし・未取得・
未認証・取得失敗・gh未導入・SSH非対応・ブランチなし（detached HEAD）・タイムアウトのいずれかです。
PR の行にはオープンPR件数、このブランチ自身のPRとその下書き状態・レビュー判定、
自分のレビュー待ちのPR件数を表示します。

## コマンドライン

| 形式 | 動作 |
|---|---|
| `git-dashboard-tui` | ダッシュボードを起動 |
| `git-dashboard-tui PATH` | PATH のリポジトリを選択した状態で起動 |
| `git-dashboard-tui --json` | 登録済みリポジトリの状態スナップショットを出力して終了 |
| `git-dashboard-tui PATH --json` | そのリポジトリ1件のスナップショット |
| `-h` / `--help` · `-V` / `--version` | 使い方 / バージョン |
| `--` | 以降をオプションとして解釈しない（`--json` という名前のディレクトリも開けます） |

`PATH` は登録済みリポジトリの隣に `(未登録)` として表示・選択されます。`config.json` には
書き込まないため、使い捨てのクローンで実行しても設定が増えません。すでに登録済みのパスは
行を重複させず既存の行を選択し、リポジトリでないパスは端末を初期化する前にエラーになります。
リポジトリ横断の機能は従来どおり登録済みの全リポジトリを対象とします。

終了コードは成功が `0`、解釈できないコマンドラインが `2`、設定または指定パスを読めなかった
場合が `1` です。

### `--json` の出力

`--json` は端末を初期化しないためパイプに流せます。またネットワークアクセスを一切行いません。
数秒ごとにステータスラインから呼ばれる用途で GitHub API を叩き続けるわけにはいかないためです。
そのため CI と PR の項目はダッシュボードが書き込んだキャッシュから読み、値がない場合や古い場合は
それらしいゼロを返さずその旨を示します。ローカルのGit状態は、ダッシュボードと同じコマンド・
同じタイムアウトでその場で取得します。

出力は配列ではなくオブジェクトです。スキーマ名とバージョンを持たせ、後から項目を追加できる
ようにするためです。`schema_version` は互換性を壊す変更のときだけ上げます。項目の追加は
それに当たりません。

| 項目 | 意味 |
|---|---|
| `schema` | 常に `git-dashboard-tui.status-snapshot` |
| `schema_version` | 現在は `1` |
| `tool_version` | 出力したバイナリのバージョン |
| `generated_at` / `generated_at_unix` | UTC の RFC 3339 / エポック秒 |
| `repository_count` | `repositories` の要素数 |

| リポジトリの項目 | 意味 |
|---|---|
| `name` / `path` / `group` | 登録内容のまま。`group` 未設定時は `null` |
| `registered` | `config.json` にない PATH 引数の場合は `false` |
| `ok` / `error` | 読み取れなかった場合は `false` と1行の理由。以下の計測値はすべて `null` |
| `branch` | 現在のブランチ。detached HEAD では `""` |
| `has_upstream` | upstream を追跡しているか |
| `ahead` / `behind` | upstream がない場合は `0` ではなく `null` |
| `uncommitted` / `conflicts` | 未追跡を含む porcelain の件数 / 未解決パスの件数 |
| `operation` | `none`・`merge`・`rebase`・`cherry_pick`・`revert` |
| `last_commit` / `last_commit_unix` | HEAD コミットの日時 |
| `github` | 下記のキャッシュのみを読む CI・PR ブロック |

| `github` の項目 | 意味 |

## 設定ファイル

設定はプレーンな JSON で、アトミックに書き込まれ、`git-dashboard` GUI アプリと共有されます。

- **macOS**: `~/Library/Application Support/com.git-dashboard.git-dashboard/`
- **Linux**: `~/.config/git-dashboard/`
- **Windows**: `%APPDATA%\git-dashboard\git-dashboard\config\`

| ファイル | 内容 |
|---|---|
| `config.json` | 登録済みリポジトリ（名前・パス・グループ） |
| `members.json` | チームメンバーと、そこへ統合するコミット作者の別名 |
| `prefs.json` | 言語・テーマ・サイドバー・差分トグル・最近の比較・ソート順・自動更新間隔・外部 diff コマンド・エディタコマンドと終了待機・独自の作業ツールコマンド・初回案内の表示済み状態・Worktreeのメモとお気に入り |
| `tech_rules.json` | マニフェストファイルから言語/フレームワークのバージョンを検出するルール |
| `cache/` | Home 行とリポジトリ解析結果のキャッシュ。更新が終わるまで空欄にせず、前回の内容を即座に表示するために使います。削除しても次回更新時に再生成されます |

ほとんどの設定はアプリ内（`s` で設定画面）から変更できます。手で編集する必要はありません。

### 外部 diff ツールを使う

設定画面で `c` を押すと、内蔵ビューアの代わりに別ツールへ差分を渡せます。コマンドには
`{path}` `{range}` `{base}` `{target}` `{file}` のプレースホルダを含められます。空にすると
内蔵ビューアに戻ります。プログラムは `PATH` から解決するか絶対パスで指定してください —
相対パスは意図的に拒否されます。子プロセスは**表示中のリポジトリ**を作業ディレクトリとして
起動するため、`./tool` のような指定はそのリポジトリ同梱のバイナリを実行してしまうからです。

### 独自の作業ツールコマンド

設定画面の `x`、または `O` ツールメニュー内の `x` で、シェル・エディタ・lazygit・GitUI に加えて
独自のコマンドを6件まで登録できます。各コマンドは名前・コマンド行・終了待機フラグ（`w`。端末を
占有するプログラムはオン、GUI はオフ）を持ち、`O` メニューでは `1` – `6` として並びます。

コマンドには `{path}`（リポジトリまたは Worktree のルート。子プロセスの作業ディレクトリでもあります）、
`{file}`（表示中ファイルの絶対パス）、`{line}`（差分画面が表示している1始まりの行番号）、
`{branch}`、`{hash}` を使えます。**その画面で値を持たないプレースホルダがあると、空文字に
置き換えず、どれが欠けているかを示して起動を中止します。** 引数が1つ消えると後ろの引数が
その位置にずれ込み、`""` を渡すとツールが黙って別のものを開いてしまうためです。
プレースホルダを1つも含まないコマンドには、既定の `code` と同じくリポジトリルートを
最後の引数として渡します。

置換する値はいずれも、登録しただけのリポジトリ由来のテキストです。そのため制御文字を含む値や、
引数を `-` で始めてしまう値は拒否し、プレースホルダが実行ファイル名になることもありません。
コマンドはシェルを介さず実行ファイルと引数に分解するため、alias・`~`・`$HOME`・パイプ・
リダイレクトは展開しません。外部 diff ツールと同様、プログラムは `PATH` から解決するか
絶対パスで指定します。未知の `{...}` はそのまま残すので、ツール側の書式指定も書けます。

### SSH 越しのリモートリポジトリ

`ssh://host/absolute/path` の形式で登録します（host は `~/.ssh/config` のエイリアスでも可）。
状態・ログ・差分・貢献者分析は、更新のたびに 1 本の多重化した SSH 接続で実行されます。認証は
鍵認証のみで、`BatchMode=yes` によりパスワード待ちで止まることはありません。ローカルの
シェル・エディタ・Gitクライアント起動、GitHub PR/CI情報、横断Worktree一覧は利用できません。
これは `ssh://…` 形式の登録に対する制限で、origin が SSH URL のローカルクローンとは異なります。


## 設定を分離する

`GIT_DASHBOARD_CONFIG_DIR` に設定先の絶対パスを指定します。存在しないディレクトリは設定保存時に作成します。以下のように事前に作成しても構いません。

```bash
mkdir -p "$HOME/.gdt-demo-config"
GIT_DASHBOARD_CONFIG_DIR="$HOME/.gdt-demo-config" git-dashboard-tui
```

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE/.gdt-demo-config" | Out-Null
$env:GIT_DASHBOARD_CONFIG_DIR = "$env:USERPROFILE/.gdt-demo-config"
git-dashboard-tui
```

## 応答性の測定

Linux aarch64の一時ディレクトリで、15,000個のディレクトリと50個の合成Gitリポジトリを用意しました。
実TUIでの1回の測定では、全50件の検出完了が0.257秒、中止からHomeの表示確認まで67.2msでした。
中止時間には観察用の待ち時間が含まれます。

これはこの環境・データでのスモーク測定です。複数回の中央値やp95、低速ディスク・ネットワーク
ファイルシステムでの性能、50リポジトリすべてのGit解析時間を示すものではありません。
走査の中止はファイルシステム操作の間で協調的に行い、OS内で停止したI/O自体を強制中断しません。

## 開発・検証

改善を個別コミットに分けました。

- `e2b670b`：未追跡・初回コミット前の一覧と差分
- `059545b`：Finderのバックグラウンド化・中止・順次表示
- `7638c28`：短いWorktree名の表示
- `57a48ae`：未追跡ファイルをフォルダではなくファイル単位で集計
- `9eaa34e`：v0.4.0の資料と公開手順
- `efda04f`：ファイルシステムの列挙順に依存しないFinderの選択テスト

macOS CIで、従来テストが選択行を常に0番と仮定していた問題が発覚しました。
非同期の検出順と最終的なソート順が異なるケースを明示的にテストし、選択対象の保持を確認しました。
最初のCI失敗を成功扱いにはしていません。

配布バイナリの実操作検証はLinux ARM64で行いました。他OSのCI成功は、各OSでの対話操作をすべて検証した意味ではありません。

## 残る製品上の制約

- 「次に着手する場所」はGitの状態から判断する範囲です。Issueの担当やビジネス上の優先順位を決めるものではありません。
- GitHub CIはリポジトリ全体の最新1実行で、現在ブランチ・全ワークフローの成功を保証しません。
- GitHubだけの強制更新キーはありません。成功後5分、失敗後1分のキャッシュ規則が適用されます。
- SSH登録のローカルツール起動、GitHub取得、横断Worktree一覧は非対応です。
- エディタやGitクライアントの全組合せを実OS上で起動検証したわけではありません。
- キー操作の学習負担、初見の完遂率、継続利用は実際の利用者で確認する必要があります。

## 再評価の結論

状態確認の具体的な不整合と操作停止の問題を改善し、複数リポジトリを扱う開発者に
試用を勧められる根拠は増えました。紹介内容と配布版の不一致も解消しています。一般利用者の使いやすさや
継続利用、競合優位については未検証と評価します。
